## 🎬 О проекте

**Tech Card Manager (TCM)** переносит **Technical Specifications**, уже содержащиеся в NFO-файлах, в реальный интерфейс просмотра Emby.

Большинство медиатек уже хорошо показывает:

* Название
* Актёрский состав
* Год
* Разрешение
* Видеокодек
* Аудиокодек
* Сведения о потоке, например HDR / Dolby Vision

Однако производственные сведения обычно не представлены полно и структурированно, например:

* Какие камеры использовались
* Какие объективы использовались
* Какие форматы плёночной или цифровой съёмки использовались
* Какие кинематографические процессы применялись
* Какие форматы звука использовались
* Какие соотношения сторон использовались
* Как произведение мастерилось и представлялось

TCM сканирует настроенные пользователем NFO-файлы фильмов и сериалов **только для чтения**, создаёт собственный производный индекс и показывает характеристики на страницах сведений с помощью веб-карточки Emby.

Основные цели TCM:

* Перенести существующие Technical Specifications в интерфейс просмотра медиатеки
* Оставлять исходные NFO-файлы строго доступными только для чтения
* Не присваивать существующий пользовательский процесс метаданных
* Управлять и обновлять медиатеки фильмов и сериалов как отдельные пространства
* Безопасно обслуживать веб-карточку Emby Technical Specifications
* Предоставлять интерфейс Windows, системный трей и локальную службу для длительной работы
* Делать важные состояния, ошибки и операции обслуживания наблюдаемыми и проверяемыми
* Включать упрощённый китайский, традиционный китайский и английский (США), а французский, русский, японский, испанский и тайский предоставлять пакетами, привязанными к версии

## ✨ Основные возможности

### 📚 Индексирование NFO только для чтения

TCM читает настроенные папки фильмов и сериалов и извлекает из NFO Technical Specifications и другие сведения только для чтения, необходимые для отображения и идентификации.

Для TCM NFO-файлы медиатеки — **источники данных только для чтения**.

TCM не выполняет следующие действия:

* Не изменяет NFO-файлы
* Не реорганизует NFO-файлы автоматически
* Не «исправляет» NFO-файлы автоматически
* Не записывает Technical Specifications
* Не создаёт и не удаляет теги
* Не изменяет владельца тегов
* Не меняет исходное содержимое NFO-файлов

Данные индекса TCM хранит отдельно.

Исходные медиаметаданные остаются под контролем пользователя и инструментов, уже применяемых в его процессе.

---

### 🖥️ Веб-карточка Emby Technical Specifications

TCM преобразует индексированные технические характеристики в данные для представления в медиатеке и интегрирует их в Emby через веб-карточку.

Текущие возможности:

* Создание карточки Technical Specifications
* Представление карточки Technical Specifications
* Раздача ресурсов карточки
* Интеграция с веб-интерфейсом Emby
* Установка веб-карточки
* Обновление веб-карточки
* Удаление веб-карточки
* Определение состояния веб-карточки
* Определение совместимости устаревших компонентов
* Обязательные процессы резервирования и восстановления

Обслуживание веб-карточки и медиаданные NFO — совершенно разные области операций.

TCM может обслуживать файлы веб-интеграции Emby, но **в этом процессе не изменяет NFO-файлы медиатеки**.

Менеджер мгновенно переключается между упрощённым китайским, традиционным китайским и английским (США) без перезагрузки и очистки текущего состояния интерфейса. Французский, русский, японский, испанский и тайский предоставляются отдельными ресурсами GitHub Release `v4.1.0` и загружаются только после скачивания и проверки. У веб-карточки Emby есть независимый реестр локалей; отсутствующая или неподдерживаемая локаль Emby возвращается к упрощённому китайскому. Ключи Technical Specs, такие как `Camera` и `Sound mix`, и структура данных не меняются вместе с языком отображения.

### 🎬 Раздельное управление фильмами и сериалами

Фильмы и сериалы являются отдельными медиапространствами TCM.

У них независимы:

* Корневые каталоги
* Индексы
* Поиск
* Фильтры
* Просмотр
* Области обновления
* Отображение состояния

Например:

```text
Фильмы
  ↓
Обновить текущую медиатеку
  ↓
Сканировать только каталоги фильмов
```

Обновление фильмов не запускает автоматическое сканирование каталогов сериалов.

А обновление сериалов не запускает повторное сканирование фильмов.

### 🔎 Просмотр и проверка индекса

Менеджер TCM предназначен не только для запуска службы. В нём можно просматривать уже построенный медиаиндекс.

Сейчас он показывает:

* Количество индексированных названий
* Общее количество NFO
* Состояние кэша / индекса
* Ошибки разбора XML
* Доступность медиатеки
* Каталоги фильмов и сериалов
* Technical Specifications
* Технические теги и другие сведения только для чтения
* Пути NFO
* Текущие задачи
* Состояния ошибок

При ошибке TCM сохраняет по возможности полезные диагностические данные: название, тип мультимедиа, путь NFO и задачу.

После сворачивания окна TCM продолжает работать в системном трее.

Сейчас поддерживаются:

* Сворачивание в системный трей

## 🔄 Основной процесс

```text
Медиа-NFO
    ↓
Сканирование и разбор только для чтения
    ↓
Производный индекс TCM
    ↓
Локальная служба / Ресурсы карточки
    ↓
Веб-карточка Emby
    ↓
Technical Specifications в медиатеке
```

TCM не записывает результаты индекса обратно в медиа-NFO.

TCM можно рассматривать как адаптер только для чтения между:

```text
Слой данных NFO
    ↓
   TCM
    ↓
Слой представления Emby
```

Он читает существующие технические характеристики, создаёт собственный индекс представления и передаёт сведения интерфейсу медиатеки.

## 🔗 Связь с IMDb Tech Manager (ITM)

TCM и [**IMDb Tech Manager (ITM)**](https://github.com/Eric-Hou1997/IMDb-Tech-Manager) — два независимых инструмента.

Они совместно работают в одном процессе **Technical Specifications**.

### 📦 IMDb Tech Manager (ITM)

ITM главным образом отвечает за создание и обслуживание исходных данных, включая:

* Получение IMDb Technical Specifications
* Структурирование Technical Specifications
* Нормализацию Technical Specifications
* Управление NFO
* Запись Technical Specifications
* Создание технических тегов
* Семантическую обработку с помощью ИИ
* Ручное исправление
* Пакетную обработку
* Обслуживание метаданных

---

### 🖥️ Tech Card Manager (TCM)

TCM главным образом отвечает за последующее чтение, индексирование, представление и интеграцию с медиатекой:

* Чтение существующих NFO-файлов только для чтения
* Построение производного индекса Technical Specifications
* Управление веб-карточкой Emby
* Представление технических характеристик на страницах медиатеки

Вместе они образуют полный процесс:

```text
IMDb
  ↓
IMDb Tech Manager (ITM)
  ↓
NFO / Technical Specifications
  ↓
Tech Card Manager (TCM)
  ↓
Карточка Emby Technical Specifications
```

TCM **не требует ITM**.

Можно использовать любой другой источник, если NFO содержит совместимые данные Technical Specifications, которые распознаёт TCM.

## 🚫 Границы продукта

У Tech Card Manager намеренно строгая область ответственности.

TCM **не**:

* Получает данные с IMDb
* Изменяет медиа-NFO
* Записывает Technical Specifications
* Создаёт Technical Tags
* Удаляет теги
* Изменяет пользовательские теги
* Запускает ИИ
* Управляет промптами
* Учитывает использование токенов ИИ
* Учитывает расходы API ИИ
* Присваивает медиаметаданные NFO
* Переносит владение NFO

Эти задачи относятся к инструментам управления данными, таким как IMDb Tech Manager.

TCM сосредоточен на одном:

**Безопасно читать существующие данные и надёжно их представлять.**

---

## 🔒 Безопасность данных и веб-интеграции

### NFO-файлы остаются доступными только для чтения

Во время:

* Сканирования
* Индексирования
* Обновления
* Поиска
* Представления

TCM должен оставлять содержимое медиа-NFO неизменным.

NFO, который невозможно разобрать, записывается как ошибка, а не исправляется автоматически.

---

### Восстанавливаемое обслуживание веб-карточки

Установка, обновление или удаление веб-файлов Emby полностью отделены от медиа-NFO.

Эти операции обслуживания должны:

* Подтверждать точную цель
* Создавать резервную копию
* Проверять возможность восстановления копии
* Строить полный изменённый результат
* Сохранять требуемое поведение BOM / концов строк
* Проверять результат после завершения
* Откатываться при сбое

Операции, требующие прав администратора, явно выполняются через Windows UAC.

---

### Осторожный перенос устаревших компонентов

TCM сохраняет проверку совместимости для выбранных устаревших компонентов, старых Web Patches и следов прошлых установок.

Для операций с побочными эффектами, таких как:

* Удаление старых компонентов
* Завершение процессов
* Замена Web Patches
* Очистка исторических файлов

предусмотрен процесс:

```text
Определить цель
    ↓
Показать план обслуживания
    ↓
Подтверждение пользователя
    ↓
Повторно проверить цель
    ↓
Выполнить
    ↓
Проверить результат
```

Если TCM не может надёжно определить владельца устаревшего компонента, он останавливается, чтобы не допустить небезопасного удаления.

## 📦 Установка и использование

### 1. Загрузка

Перейдите на:

[**GitHub Releases →**](https://github.com/Eric-Hou1997/Tech-Card-Manager/releases)

Проект не публикует отдельный голый `.exe` как ресурс Release.

Текущий официальный пакет:

```text
TCM-v4.1.0-Windows-x64-EXE.zip
```

---

### 2. Полностью распакуйте ZIP

Сначала полностью распакуйте ZIP в постоянный каталог.

Затем запустите:

```text
Tech-Card-Manager.exe
```

Не запускайте приложение прямо из сжатого архива.

---

### 3. Настройте медиатеки

После первого запуска настройте в Менеджере нужные корни медиатек.

Корни фильмов и сериалов настраиваются отдельно.

Например:

```text
Фильмы
  └── D:\Movies

Сериалы
  └── D:\TV
```

TCM читает соответствующие NFO-файлы из этих каталогов.
TCM также может автоматически обнаруживать каталоги медиатеки в Emby Server.

---

### 4. Постройте индекс

Обновите медиатеку, соответствующую текущему пространству фильмов или сериалов.

```text
NFO
 ↓
Разбор
 ↓
Производный индекс
```

Процесс не записывает данные индекса обратно в NFO-файлы.

---

### 5. Настройте веб-карточку Emby

Следуйте состоянию и инструкциям Менеджера, чтобы установить или обслужить веб-карточку Emby.

Windows может запросить права администратора, если нужно изменить веб-файлы Emby.

---

### 6. Оставьте TCM работающим

TCM предоставляет локальную службу, через которую веб-карточка обращается к индексу и связанным ресурсам.

Поэтому во время использования карточки Technical Specifications TCM должен продолжать работать.

Менеджер можно свернуть в трей; ему не требуется оставаться видимым на рабочем столе.

---

Рекомендуемый процесс обновления:

```text
Проверить новую версию
    ↓
```

## 🤖 Разработка с Coding Agents

Репозиторий содержит:

[**`AGENTS.md` →**](../../AGENTS.md)

Это одна из главных отправных точек контекста для Coding Agents, таких как Codex, при работе с Tech Card Manager.

Он описывает:

* Идентичность продукта
* Границы репозитория
* Разделение ответственности TCM и ITM
* Правила NFO только для чтения
* Границы индексирования Technical Specifications
* Правила безопасности веб-карточки
* Правила идентификаторов совместимости устаревших компонентов
* Правила жизненного цикла Windows
* Ограничения UAC и административного обслуживания
* Требования к тестированию
* Границы Release
* Запрещённые изменения

Рекомендуемый процесс разработки:

```text
Fork / Clone
        ↓
Coding Agent читает AGENTS.md
        ↓
Прочитать относящийся к задаче код и тесты
        ↓
Подтвердить границы продукта TCM
        ↓
Проанализировать затронутые функциональные пути
        ↓
Создать план реализации
        ↓
Изменить код
        ↓
Запустить тесты
        ↓
При необходимости проверить в реальной среде Windows / Emby
        ↓
Отправить Pull Request
```

Репозиторий стремится предоставить:

```text
Исходный код
  +
Знание архитектуры
  +
Проектные ограничения
  +
Методы тестирования
  +
Контекст агента
```

Это снижает риск того, что разработчик или Coding Agent случайно нарушит границы продукта при изменении проекта.
