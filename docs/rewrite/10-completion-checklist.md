# 第 9–12 步逐项实施与验收

本清单重新按维护者指令建立。每行必须有对应实现和证据才可勾选；构建、安装烟测、静态测试不替代完整业务和桌面验收。此前 18 个包是验证包。

## 第 9 步：TCM Emby 集成和生命周期

- [ ] 只读 NFO → 索引 → 卡片数据 → 资源发布 → Emby 加载 → 实际卡片展示 → 服务停止与清理完整通过。
- [ ] Emby 环境发现、版本检查、安装目录与数据目录配置、路径映射。
- [ ] 安装、更新、修复、禁用、移除与重复操作。
- [ ] 历史组件识别、可审查维护计划、明确确认、权限申请与失败恢复。
- [ ] 外部备份、事务提交、并发修改保护、中断回滚。
- [ ] Web Card 数据与八种语言发布；Manager 与卡片发布状态分别显示。
- [ ] 服务启停、后台运行、租约失效、异常退出和正常退出清理。
- [ ] Emby 升级后自动重新检查与可操作修复。
- [ ] macOS/Linux 独立路径与权限适配。
- [ ] Windows ARM64 Manager 与真实 Emby 安装组合验证。

## 第 10 步：完整界面与系统行为

- [ ] 两产品每个原版页面、按钮、菜单、设置、快捷入口都有对应实现。
- [ ] 表格排序、搜索、筛选、选中项、布局状态持久化。
- [ ] Movie/TV 独立状态、TV 层级、季选择、批量范围准确。
- [ ] 长任务真实进度；错误可回到受影响项目。
- [ ] 最小化、关闭窗口、后台运行、完全退出、二次启动与登录启动。
- [ ] 原生菜单、托盘、对话框、权限和错误提示语言一致。
- [ ] 三种内置语言与五种外部语言包；切换不丢失界面或任务状态。
- [ ] 八种语言、窄窗口、缩放、键盘与无障碍操作验收。
- [ ] Linux 缺少托盘等能力时有等效入口，并记录真实平台差异。

## 第 11 步：数据迁移与 OTA

- [ ] 旧配置、媒体库、路径映射、提示词、凭据、索引、缓存、备份、任务历史和启动设置逐字段迁移。
- [ ] 迁移可重复执行、中断恢复、回退；旧数据保留且不可静默丢弃。
- [ ] 产品、系统、应用架构、安装渠道精确选择更新产物。
- [ ] macOS ARM64 DMG 初装和应用内更新。
- [ ] Windows x64/ARM64 一次点击下载、验签、安装、重启及结果验证。
- [ ] Linux x64/ARM64 AppImage 应用内更新。
- [ ] Linux x64/ARM64 DEB/RPM 签名软件源及包管理器升级方案。
- [ ] Windows ARM 机器上的旧 x64 安装保持应用架构，避免重复安装和数据目录变化。
- [ ] 应用替换失败与数据迁移失败分别恢复；没有无法判断的半安装状态。
- [ ] 旧 OTA 签名与新格式兼容验证；既有密钥不自动更换。
